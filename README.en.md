# Mineradio Web TSBot

Mineradio Web TSBot is a TeamSpeak music player with an immersive web visual
system. It combines a Rust TeamSpeak voice client, a FastAPI control backend,
and a framework-free JavaScript/Three.js console for playback, lyrics, audio
analysis, and responsive visuals.

[中文](README.md) · [Run and deploy](HOWTOSTART.md) ·
[API reference](docs/API.md) · [Frontend development](web/README.md) ·
[Logging](LOGGING.md)

## Highlights

- TeamSpeak playback with queue, play/pause, skip, volume, shuffle, and repeat.
- Mineradio-style web console with dark glass UI, a 3D shelf, search, playlists,
  and immersive mode.
- Three visual presets: Particle Wall, Galaxy, and Sonic Topography. Sonic
  Topography reacts to realtime or analyzed audio frames, beats, terrain, and
  water-drop ripples.
- Three lyric modes: original, translation, and original plus translation,
  with line highlighting and sweep timing aligned to lyric boundaries.
- Shared audio-analysis cache keyed by song name, next-track pre-analysis, and
  analysis status indicators on shelf cards.
- Local browser wallpapers. Selected videos stay in the browser and are never
  served or uploaded by this project.
- Built-in QQ Music and Bilibili adapters. The legacy Netease adapter remains
  optional compatibility code and is not required for the main project flow.
- Secure defaults: API authentication is enabled by default, while backend and
  voice gRPC ports bind to loopback in Compose.

## Architecture

```text
Browser (Vite + vanilla JavaScript + Three.js)
        │ HTTP / WebSocket
        ▼
FastAPI backend ── gRPC ──► Rust voice-service ──► TeamSpeak
        │
        ├── audio analysis and shared cache
        ├── QQ Music / Bilibili adapters
        └── SQLite, admin sessions, and runtime settings
```

Key directories:

- `web/`: player UI, lyrics, shelf, visual settings, local wallpapers, and Three.js scenes.
- `backend/`: HTTP/WebSocket API, queue, analysis cache, authentication, and database.
- `voice-service/`: Rust TeamSpeak client, audio processing, and gRPC server.
- `proto/`: backend/voice-service protocol definitions.
- `docker-compose*.yml` and `Dockerfile.*`: source, prebuilt, and offline container deployment.
- `tests/` and `web/tests/`: backend regression, release-security, and frontend contract tests.

## Quick start

Docker Compose is the recommended path:

```bash
cp tsbot.env.example tsbot.env
# Set TeamSpeak values, a cookie key, an API token, and an admin token.
docker compose up -d --build
docker compose ps
```

Open `http://127.0.0.1:8080`. Stop the stack with:

```bash
docker compose down
```

The default setup persists SQLite data in `./data` and logs, identity files,
and initial-password output in `./logs`. See [HOWTOSTART.md](HOWTOSTART.md) for
local development, Windows scripts, prebuilt images, reverse proxy, upgrades,
and rollback.

### Use prebuilt images from Docker Hub or GHCR

If you do not want to compile locally, pull the three images published by
Actions. Copy and edit the environment file first:

```bash
cp tsbot.env.example tsbot.env
# Set TSBOT_COOKIE_KEY, API/admin tokens, and TeamSpeak values.
```

Docker Hub public images for this project (namespace: `lightningcloude`):

```bash
export TSBOT_IMAGE_REGISTRY="docker.io"
export TSBOT_IMAGE_NAMESPACE="lightningcloude"
export TSBOT_IMAGE_REPO="mineradio-web-tsbot"
export TSBOT_IMAGE_TAG="latest"
# Public images do not require docker login. For production, use a fixed tag such as sha-758d2a5.
docker compose --env-file tsbot.env -f docker-compose.prebuilt.yml pull
docker compose --env-file tsbot.env -f docker-compose.prebuilt.yml up -d
```

The three Docker Hub images are:
`lightningcloude/mineradio-web-tsbot-backend`,
`lightningcloude/mineradio-web-tsbot-web`, and
`lightningcloude/mineradio-web-tsbot-voice-service`.

GHCR:

```bash
export TSBOT_IMAGE_REGISTRY="ghcr.io"
export TSBOT_IMAGE_NAMESPACE="lightningcloude"
export TSBOT_IMAGE_REPO="mineradio-web-tsbot"
export TSBOT_IMAGE_TAG="latest"
# Public images need no login. For private images:
# echo "$GHCR_TOKEN" | docker login ghcr.io -u LightningCloude --password-stdin
docker compose --env-file tsbot.env -f docker-compose.prebuilt.yml pull
docker compose --env-file tsbot.env -f docker-compose.prebuilt.yml up -d
```

The three image suffixes are `-backend`, `-web`, and `-voice-service`. `latest`
tracks `main`; production deployments should prefer an immutable
`sha-<commit>` tag generated by Actions.

## Secure configuration

Copy `tsbot.env.example` and keep the real file out of Git. At minimum, set:

```bash
export TSBOT_COOKIE_KEY="a-long-random-secret-of-at-least-32-characters"
export TSBOT_API_TOKEN="api-access-token"
export TSBOT_ADMIN_TOKEN="admin-operation-token"
export TSBOT_TS3_HOST="your-teamspeak-server.example"
export TSBOT_TS3_PORT="9987"
export TSBOT_TS3_NICKNAME="mineradio-tsbot"
export TSBOT_TS3_CHANNEL_ID="2"
```

Generate secrets with `openssl rand -hex 32`. Normal APIs accept
`Authorization: Bearer <token>` or `x-api-token`. If the server-side token is
missing, the authentication middleware fails closed instead of exposing APIs.

## Default ports

| Service | Port | Default exposure |
| --- | ---: | --- |
| Web console | 8080 | Host entry point |
| FastAPI backend | 8009 | `127.0.0.1` |
| voice-service gRPC | 50051 | `127.0.0.1` |
| Vite development server | 5173 | Local development |

In production, expose only an HTTPS-protected Web entry point. Do not publish
8009 or 50051 directly to the Internet.

## Local development

The supported baseline is Python 3.11, Node.js 20.19+, Rust 1.88, plus CMake,
a C/C++ toolchain, and FFmpeg for local voice-service builds.

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
npm --prefix web ci
cargo build --manifest-path voice-service/Cargo.toml --locked
```

Use `run-backend.*`, `run-web.*`, and `run-voicemake.*` to start the individual
components. See [web/README.md](web/README.md) for frontend boundaries,
proxy paths, and visual-system constraints.

## Tests and build

```bash
python -m unittest discover -s backend/tests -v
python -m unittest discover -s tests -v
npm --prefix web test
npm --prefix web run build
cargo test --manifest-path voice-service/Cargo.toml --locked
```

CI runs these checks in clean environments, plus npm audit, Cargo lockfile
verification, and Docker release-package checks. After deployment,
`verify-deployment.*` can run read-only API and browser acceptance checks.
